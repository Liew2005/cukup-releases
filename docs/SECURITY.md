# Security

Cukup is a single-user app that holds personal financial data, so the defaults are conservative.

## Authentication

- **Password** hashed with PBKDF2-SHA256 (`pbkdf2.<iterations>.<salt>.<hash>`), generated by `worker/scripts/hash-password.mjs` or `rotate-secrets.mjs`. The plaintext is never stored.
- **Sessions** are HS256 JWTs signed with a random secret, valid for 30 days. Rotating the secret signs everyone out.
- **Two-factor (optional).** `worker/scripts/setup-2fa.mjs` creates a TOTP secret and verifies a code before saving it. When enabled the code is checked on every login, and the error message never reveals which factor failed.
- **Brute-force protection.** Five failed logins per IP in 15 minutes returns `429`. Failed attempts are stored in D1 and cleared on success.
- All routes except `/health` and `/auth/*` require a valid token.

## Secrets

Secrets live only in Cloudflare Worker secrets (`APP_PASSWORD_HASH`, `JWT_SECRET`, `GEMINI_API_KEY`, optional `TOTP_SECRET`). Nothing secret is in source control. The Android signing keystore, `key.properties`, `.dev.vars` and `.env` files are git-ignored. The app keeps its session token in the platform secure storage.

The helper scripts that set secrets read the password from a hidden prompt and print nothing.

## On the phone

- Optional fingerprint or PIN lock covers the app on launch and after it has been in the background.
- Receipt photos are read on the device. Only the extracted text is sent to the server.
- From the phone contacts, the app receives only the single contact the user taps.
- Payment detection is opt-in through Android's notification access setting. Only notifications from an allowlist of wallet, Google Wallet and bank apps are examined; everything else is dropped without being read further. Personal text messages are never logged. Digit runs of six or more (four or more for skipped notifications) are masked before anything is written, so one-time codes, card and account numbers do not end up in the log. The log stays in app-private storage and leaves the phone only if the user shares it. A detected payment becomes an entry only after an explicit Save.

## Data handling

- Input is validated on the server: types, ranges, whole-cent amounts, ID formats and list sizes.
- CSV export neutralises formula injection.
- The OTA updater only accepts an `https` APK link, and Android's package installer refuses an update that is not signed with the same key as the installed app.

## Reporting an issue

This is a personal project. If you spot a vulnerability, please open a private security advisory on the repository.
